# Руководство для контрибьюторов

Этот форк таико-веба живёт на продакшн-сценариях, поэтому каждая правка должна сохранять актуальное поведение и покрываться проверками.

## Инварианты веб-режима

* **Обязательные зависимости.** Стек запускается из `docker-compose.yml` тремя сервисами: `mongo`, `redis` и `web`. Контейнер `web` обязан ждать успешные healthcheck-и MongoDB и Redis перед стартом и использовать их по умолчанию без кастомных переменных.
* **Healthcheck.** Эндпоинт `/healthz` доступен без авторизации и возвращает HTTP 200 и JSON `{"status": "ok"}`, только если и MongoDB, и Redis отвечают. Любые регрессии в доступности или формате ответа считаются критичными.
* **Базовый путь и публичные API.** Значение `BASEDIR` по умолчанию `/`, поэтому страницы и API доступны по корню (`/`, `/api/csrftoken`, `/api/songs`). Эти роуты должны продолжать работать без предварительного наполнения базы.
* **Поведение по умолчанию.** Сканы песен и фоновые задачи включены через `config/config.py`; smoke-тесты допускают пустые директории `songs`, поэтому изменения не должны требовать дополнительных ручных подготовок.
* **Проверки инвариантов.** Скрипт `scripts/smoke_web.sh` и тест `tests/web_compat_test.py` обязаны оставаться зелёными. Они поднимают docker-compose стек, ждут `/healthz` и запрашивают публичные API, фиксируя базовый контракт веб-режима.

Следуйте этим инвариантам при доработках и дополняйте smoke/e2e тесты, если появляются новые критичные сценарии.
